Study of Open-Source Software

Hermes Agent

Hermes Agent is an open-source, self-improving AI agent from Nous Research. It can run locally or on a remote machine and can be accessed through a terminal, a web interface, or messaging platforms.

Its main idea is to combine an LLM with tools, persistent memory, reusable skills, scheduled jobs, and multiple communication channels. The project is MIT licensed.

  • It demonstrates how an LLM agent connects reasoning with real-world tools.
  • It separates the model provider from the agent workflow, reducing provider lock-in.
  • It shows how memory, skills, scheduling, and messaging can turn a chat interface into an automation system.
  • Its source code is available for inspection, extension, and contribution.

Hermes can search past conversations, maintain persistent knowledge, and create or improve skills based on experience. This creates a feedback loop between completed work and future behavior.

Users can select providers such as Nous Portal, OpenRouter, OpenAI, or a compatible custom endpoint. The hermes model command changes the selected model without changing the agent code.

The agent can use local execution or terminal backends such as Docker, SSH, Singularity, Modal, Daytona, and Vercel Sandbox. This lets the conversation interface stay separate from the environment doing the work.

Hermes provides an installer for Linux, macOS, WSL2, and Termux. Native Windows is also supported through PowerShell.

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.zshrc
hermes

For Windows, use the PowerShell installer documented in the upstream README. Review installation scripts before running them in a production environment.

hermes setup       # Run the setup wizard
hermes model       # Choose a provider and model
hermes tools       # Configure enabled tools
hermes config get  # Inspect configuration
hermes doctor      # Diagnose installation problems
hermes update      # Update Hermes

  • CLI/TUI: interactive terminal conversations with streaming output, history, multiline editing, and slash commands.
  • Gateway: a long-running process that connects Hermes to Telegram, Discord, Slack, WhatsApp, Signal, or other supported channels.
  • Scheduled delivery: cron jobs can run tasks and send reports to a configured platform.

Start the gateway with hermes gateway after configuring the required platform credentials and access controls.

Tools let the model act outside the conversation. Common categories include terminal execution, web research, browser automation, file operations, code execution, and integrations through MCP.

Skills are reusable procedural instructions. A skill can package domain knowledge and a repeatable workflow so the agent does not need to rediscover the process every time.

  • Conversation history supports continuity across sessions.
  • Persistent memory and user profiles help retain useful preferences and facts.
  • FTS5-based session search helps retrieve relevant past conversations.
  • Context files such as project instructions can shape behavior for a workspace.

Memory should be treated as data with privacy and retention requirements, not as an unquestioned source of truth.

  1. Receive a user request and relevant context.
  2. Ask the selected model to reason about the next action.
  3. Call a tool when work outside the model is needed.
  4. Feed the tool result back into the conversation.
  5. Repeat until the task is complete, then persist useful results.

Delegates can run isolated subagents in parallel for separate workstreams. This can reduce wall-clock time, but it increases coordination and review needs.

  • Use least-privilege API keys and messaging permissions.
  • Review command approval and DM pairing settings before exposing a gateway.
  • Prefer isolated execution backends for untrusted code or files.
  • Keep dependencies, the agent, and container images updated.
  • Do not store secrets in skills, context files, logs, or persistent memory.

  1. Read the upstream README and documentation before running the agent.
  2. Trace a simple request from the CLI into the agent loop and back to the output.
  3. Inspect the tool and skill interfaces, then follow one tool call end to end.
  4. Read the tests for the component you want to change.
  5. Run the repository test commands and document assumptions in a focused pull request.
