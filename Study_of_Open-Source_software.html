Study of Open-Source Software

Hermes Agent

Hermes Agent is an open-source, self-improving AI agent from Nous Research. It can run locally or on a remote machine and can be accessed through a terminal, a web interface, or messaging platforms.

Its main idea is to combine an LLM with tools, persistent memory, reusable skills, scheduled jobs, and multiple communication channels. The project is MIT licensed.

  • It demonstrates how an LLM agent connects reasoning with real-world tools.
  • It separates the model provider from the agent workflow, reducing provider lock-in.
  • It shows how memory, skills, scheduling, and messaging can turn a chat interface into an automation system.
  • Its source code is available for inspection, extension, and contribution.

Hermes can search past conversations, maintain persistent knowledge, and create or improve skills based on experience. This creates a feedback loop between completed work and future behavior.

Users can select providers such as Nous Portal, OpenRouter, OpenAI, or a compatible custom endpoint. The hermes model command changes the selected model without changing the agent code.

The agent can use local execution or terminal backends such as Docker, SSH, Singularity, Modal, Daytona, and Vercel Sandbox. This lets the conversation interface stay separate from the environment doing the work.

Hermes provides an installer for Linux, macOS, WSL2, and Termux. Native Windows is also supported through PowerShell.

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.zshrc
hermes

For Windows, use the PowerShell installer documented in the upstream README. Review installation scripts before running them in a production environment.

hermes setup       # Run the setup wizard
hermes model       # Choose a provider and model
hermes tools       # Configure enabled tools
hermes config get  # Inspect configuration
hermes doctor      # Diagnose installation problems
hermes update      # Update Hermes

  • CLI/TUI: interactive terminal conversations with streaming output, history, multiline editing, and slash commands.
  • Gateway: a long-running process that connects Hermes to Telegram, Discord, Slack, WhatsApp, Signal, or other supported channels.
  • Scheduled delivery: cron jobs can run tasks and send reports to a configured platform.

Start the gateway with hermes gateway after configuring the required platform credentials and access controls.

Tools let the model act outside the conversation. Common categories include terminal execution, web research, browser automation, file operations, code execution, and integrations through MCP.

Skills are reusable procedural instructions. A skill can package domain knowledge and a repeatable workflow so the agent does not need to rediscover the process every time.

Hermes has a closed learning loop: after completing a complex task, it can identify a useful repeatable procedure and turn that experience into a reusable skill. Later, the skill can be selected for a similar task instead of starting from a blank context.

When a task contains valuable steps, decisions, or troubleshooting knowledge, Hermes can capture the successful approach as a named skill with instructions and supporting context.

Skills act as procedural memory. Hermes can search or invoke a relevant skill when a later request resembles the task that produced it, making repeated work more consistent and efficient.

If a skill is incomplete or produces a weak result, the agent can refine its instructions based on the new experience. This allows a skill to become more useful over repeated applications rather than remaining static documentation.

Self-updating does not mean every generated instruction should be trusted automatically. Review skill changes, remove incorrect procedures, restrict sensitive tools, and keep important skills under version control. Hermes skills are compatible with the agentskills.io open standard.

Hermes self-learning is not one single mechanism. It is better understood as several layers of persistence and self-improvement:

Mechanism What it learns Where it persists Can it change future behavior?
User memory Facts and preferences about you USER.md Yes, indirectly
Conversation memory Useful information from past interactions MEMORY.md Yes
Skills Reusable procedures and workflows Skill files Yes
Background review What worked, what failed, and what should improve Memory or skill files Yes
Session and context history Previous conversation and tool context Session storage Temporarily or per session

USER.md represents what Hermes knows about you. It can contain preferences, typical workflows, active projects, response preferences, and repeated instructions.

For example, if you say, “I prefer Python over JavaScript,” Hermes can save that preference and use it in future conversations. This changes behavior indirectly by adding user-specific facts to future prompts.

MEMORY.md stores information that Hermes considers useful for future tasks. For example, it might remember that you are building a LangGraph multi-agent system and evaluating it with Phoenix.

The distinction is:

  • USER.md stores who you are and how you prefer to work.
  • MEMORY.md stores useful knowledge learned from previous work.

Memory means, “I remember something.” A skill means, “I learned how to do something.”

For example, Hermes could turn a repeated repository workflow into a reusable skill:

  1. Inspect the repository.
  2. Run tests and find the failing component.
  3. Modify the code and run the tests again.
  4. Prepare the completed change for review.

The next similar request can invoke that skill rather than reconstructing the workflow from scratch.

After completing work, Hermes can review what happened:

  • What went well?
  • What mistakes occurred?
  • What should be remembered?
  • Is there a reusable procedure worth turning into a skill?

The result may be an update to persistent memory or the creation and refinement of a skill. This is the mechanism to scrutinize most closely if you do not want Hermes modifying its own knowledge or behavior without permission.

Session history is not learning in the model-training sense. It is context persistence:

  • Context and history: temporary recall of previous conversation and tool context.
  • Memory: persistent recall written for future tasks.
  • Skills: persistent learned procedures.

Session history can therefore be retained for continuity without necessarily writing new information into MEMORY.md.

Hermes does not normally train the underlying LLM or modify its neural-network weights. Instead, experience is written to files or session storage and added to future prompts:

Experience → files, memory, or skills → future prompts → the same underlying LLM

For a mostly stateless setup:

  • Disable background review or automatic self-improvement in the Hermes configuration for your version.
  • Disable automatic memory and skill updates, or require approval before generated changes are saved.
  • Remove, rename, or keep USER.md, MEMORY.md, and skill directories empty or read-only.
  • Disable session-history persistence if you also do not want context retained between sessions.
  • Use hermes config get and the version-matched documentation to identify the exact configuration keys; option names can change between releases.
  • Review logs and file changes, and restrict write permissions when running Hermes with untrusted tasks.

You can keep ordinary in-session context while disabling persistent memory and automatic skill modification, depending on the level of statelessness you need.

  • Conversation history supports continuity across sessions.
  • Persistent memory and user profiles help retain useful preferences and facts.
  • FTS5-based session search helps retrieve relevant past conversations.
  • Context files such as project instructions can shape behavior for a workspace.

Memory should be treated as data with privacy and retention requirements, not as an unquestioned source of truth.

  1. Receive a user request and relevant context.
  2. Ask the selected model to reason about the next action.
  3. Call a tool when work outside the model is needed.
  4. Feed the tool result back into the conversation.
  5. Repeat until the task is complete, then persist useful results.

Delegates can run isolated subagents in parallel for separate workstreams. This can reduce wall-clock time, but it increases coordination and review needs.

Update the Hermes Agent installation to the latest available version:

hermes update

Synchronize the project's skills using the skills synchronization module:

python3 -m tools.skills_sync

  • Use least-privilege API keys and messaging permissions.
  • Review command approval and DM pairing settings before exposing a gateway.
  • Prefer isolated execution backends for untrusted code or files.
  • Keep dependencies, the agent, and container images updated.
  • Do not store secrets in skills, context files, logs, or persistent memory.

  1. Read the upstream README and documentation before running the agent.
  2. Trace a simple request from the CLI into the agent loop and back to the output.
  3. Inspect the tool and skill interfaces, then follow one tool call end to end.
  4. Read the tests for the component you want to change.
  5. Run the repository test commands and document assumptions in a focused pull request.
